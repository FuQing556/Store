# 百味饭馆验收清单

先执行 `npm test`；再用 `npm start` 或离线 `index.html` 验证页面。通过右上角“设置 → 验收与规则”进入不覆盖正式存档的实验室。打开弹窗会暂停时间，关闭后继续。时间相关场景可用 5×；精确检查边界时，在实验中暂停，然后点击“推进 1 秒（验收实验）”。此操作只推进一次引擎 Tick，仍保持暂停。

| 用例 | 复现操作 | 通过条件 | 自动化测试 |
| --- | --- | --- | --- |
| T01 | 正常新店等待30模拟秒；实验室选择“满员与排队流失” | 自然客人到访；满桌满队后新客人立即记录容量流失 | 初始间隔、满桌满队容量测试 |
| T02 | 选择“烹饪与仙女棒”；或炸弹批量拉客 | 只点可做且上架菜；订单依灶眼数量烹饪，其余等灶 | 点单过滤、FIFO、容量测试 |
| T03 | 选择“手动出餐与超时”，点击出餐；再重复场景发送“出餐”弹幕 | 成品移入用餐，5秒后现金与服务数增长、概率掉落 | 手动、弹幕、FIFO、掉落、重复结账测试 |
| T04 | 选择“手动出餐与超时”，不操作等10模拟秒 | 客人离开，成品移除，收入和掉落不增加 | 完成后计时与超时作废测试 |
| T05 | “满员与排队流失”后等待，不送自动出餐 | 排队客按耐心流失，日志可筛选“客人流失” | 排队耐心耗尽测试 |
| T06 | “研发与成长”，研发葱油饼；菜单满时尝试上架，先下架再上架 | 准确扣现金/材料；重复研发不可用；满菜单有提示；缺口明确 | 研发扣款、菜单容量、等级门槛测试 |
| T07 | “研发与成长”→小店成长→升级饭馆两次 | 桌位、排队、灶眼、菜单位、客流、菜品级同步变化，消耗准确 | 两级成长、新增座位与灶眼测试 |
| T08 | “高级菜厨师锁”→二品，查看牛肉面；升级厨师后再查看 | 已激活牛肉面显示厨师锁，升级后可制作且变快 | 厨师锁、升级门槛和在制订单变速测试 |
| T09 | “烹饪与仙女棒”，立即暂停，连续送仙女棒 | 每根减基础20%，最低保留实际总时长20%，最多4根；空灶不生效 | 四根、下限、高级厨师、空灶测试 |
| T10 | “第十抽保底”，点药丸；再多次点击直到无可激活新菜 | 第十次新菜；无新菜时转换三色各2；保底计数重置 | 所有概率区间、保底、新菜转换测试 |
| T11 | 送魔法镜4次，查看3层；过几秒再送 | 最大3层，客流×2.5；重复送恢复30秒；结束恢复基础客流 | 叠层、刷新、到期、权重测试 |
| T12 | “手动出餐与超时”后送甜甜圈，再连续送4次 | 现有成品立即出餐；新成品自动出餐；剩余最多180秒，结束恢复手动 | 立即出餐、新成品、上限、最后Tick测试 |
| T13 | 炸弹拉客后立即再试；满员时再试；菜全部下架后再试 | 数量min裁剪、高级保底、20秒冷却；空位不足/无菜不启动冷却 | 各等级人数、保底、拒绝条件与剩余容量测试 |
| T14 | 回正式饭馆，用药丸获得资源并激活菜；刷新浏览器 | 现金材料、等级、激活菜、上架与保底保留；临时客人/效果重新开始 | 成长序列化完整往返、损坏存档校验 |

## 其他验证

- 暂停时等几秒，再继续：客人和礼物时间不变化。
- 输入无效弹幕：提示支持的命令，资源不改变。
- 打开设置导出 JSON，导入同一文件：成长状态相同。损坏 JSON 不应替换当前状态。
- 实验室领取5000现金后刷新：正式存档不会获得5000现金。
- 从实验室回正式饭馆：原成长和在线客人恢复，不结算实验订单。
- 缩小至390像素：450×800画布等比缩放，主场景与控制仍可用，管理页内部滚动，不出现文档横向溢出。
- “厨师变速计时”场景默认暂停：香煎葱油饼在1级厨师开始制作，连续升级至3级，显示8秒；逐秒推进，第7秒仍烹饪，第8秒进入待出餐。点击出餐后再推进5秒，只结账一次。
- “多灶仙女棒”场景默认暂停：三单同时烹饪，连续送12根仙女棒，依次使三单各收到4根，剩余均为1.6秒（界面向上取整显示2秒）；第13根提示全部到上限。高级厨师或自然烹饪使某单提前进入最后20%时，也应跳过该单加速下一单。
- 断网后直接打开 `dist/index.html`：背景、样式、按钮、经营循环仍运行；无远程字体、脚本或图片请求。
- 运行长时间模拟测试：无负资源、重复客人/桌位、灶眼或排队容量越界。
- 首次点击解锁声音，设置中试听出锅提示；关闭音乐后只剩操作音效，静音后都停止。重新打开时不会叠加多个音乐循环。
- 暂停或打开指南时，音乐与烹饪声停止，CSS动画停止；关闭后继续原音乐位置，游戏状态正确。
- 关闭动态效果并刷新，设置保留；仍可出餐、升级和获取完整文字反馈。系统减少动态偏好优先。
- 点击礼物后等待一秒，按钮焦点保留，倒计时更新不重建整组按钮。

## 自动测试方式

```powershell
npm test
```

测试需要 Node.js 20+，使用内置 `node:test` 与严格断言，不依赖联网或 npm 安装。测试直接调用 `Game`，注入种子或精确随机值；明确设置边界状态，不以实际等待或随机碰巧事件为通过标准。
