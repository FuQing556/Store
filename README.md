# 百味饭馆 · 网页经营 Demo

源码仓库：[FuQing556/Store](https://github.com/FuQing556/Store)

技术栈：原生 HTML、CSS、JavaScript，零运行依赖。使用统一的1秒 Tick、配置表、种子随机数和 localStorage；Node.js 20+ 用于启动、测试、构建与打包。

启动命令：在项目目录运行 `npm start`，浏览器访问 http://127.0.0.1:4173/。Windows 可双击 `start.bat`。不用执行 `npm install`。

实现范围：饭馆和厨师各1–3级、12道菜、6类顾客、5种模拟礼物、自动到访/排队/点单/烹饪、手动及自动出餐、结账掉落、研发/菜单上下架、升级、本地成长存档、模拟弹幕、暂停/倍速及独立验收实验。

未实现范围：真实直播/支付/登录接口、后端、云存档、多人排行榜、外卖、宴席、装扮、离线收益和完整版成长。未部署在线游戏站点；GitHub 地址用于查看和下载源码。

最复杂的状态处理：同一 Tick 内烹饪完成、释放灶眼、订单接续、出餐超时、自动出餐及礼物到期。规则集中在纯经营引擎，动画只展示结果，不触发结账或修改资源。

如果再给一天：优先补完整浏览器回归测试，验证菜单、成长、存档与异常恢复，并完善人物动作和状态提示。

## 获取和运行

交付压缩包结构：

```text
百味饭馆.zip
├── 项目.zip
└── README.md
```

解压 `项目.zip` 后进入 `百味饭馆` 目录，再双击 `start.bat` 或执行以下命令。也可以从上方 GitHub 仓库克隆源码。

```powershell
npm start
npm test
npm run build
npm run verify
```

- Node.js 20+，不需要安装第三方依赖。
- `npm start` 启动本地服务；`start.bat` 还会自动打开浏览器。同一游戏已运行时复用原服务；其他程序占用时可运行 `npm start -- --port 4174`。
- 离线试玩可直接打开根目录 `index.html`。项目 ZIP 也附有已构建的 `dist/index.html`；从 GitHub 获取源码后可执行 `npm run build` 生成。
- 所有图片、声音和脚本均在本地，无 CDN 或外部素材请求。文件协议下的保存能力依浏览器而异，推荐使用本地服务。
- 不同浏览器、端口和文件路径的存档彼此独立。清空进度：右上角设置 → 重新开店；保留进度请先导出 JSON。仅刷新旧页面可按 Ctrl+F5。

## 玩法

1. 初始为1级折叠面摊，3桌、5个排队位、1个灶眼、3个菜单位，现金和材料为0，三道面条已激活并上架。
2. 初始约30秒来一位顾客。顾客自动入座点单，后厨按空灶制作，其余订单等待。
3. 菜完成后点击底部“出餐”，或输入模拟弹幕“出餐”；用餐5秒后结账，有概率掉落食材和铭牌。等待过久则流失，成品作废。
4. 右侧“菜谱”可研发和调整上架；“成长”可升级饭馆和厨师；“见闻”查看经营、礼物及流失日志。管理页继续营业，并提供出餐提醒和按钮。
5. 1/2/3级饭馆分别有3/4/5桌、5/6/8个排队位、1/2/3个灶眼、3/5/7个菜单位，并解锁对应品级的菜与厨师。厨师速度分别为1/1.25/1.5倍。
6. 礼物均为免费本地模拟。早期绿色、蓝色研发材料可从能量药丸获得。

| 礼物 | 规则 |
| --- | --- |
| 红色仙女棒 | 优先选择最早开始且仍可加速的订单，每根减菜品基础时长20%；每单最多4根，最低保留该单实际时长20%。达到限制后自动选下一单，全部受限或空灶时无效。提示显示目标桌号。 |
| 能量药丸 | 红/绿/蓝食材各23%（各×2）、铭牌12%（×1）、新菜8%、现金11%（×50）。连续9抽未获新菜奖励后，第10抽保底；新菜只从饭馆和厨师均达标的未激活菜中选，无可激活新菜则转三色各×2。 |
| 魔法镜 | 持续30秒，最多3层，客流倍率1.5/2/2.5；每层提高当前到访池最高两品级客人权重，重复送刷新持续时间，不能突破容量。 |
| 甜甜圈 | 每个增加60秒自动出餐，最多180秒，已有和新完成成品立即自动出餐。 |
| 炸弹 | 至少3个空桌/空排队位且有可做菜单菜时生效，招揽 min(3+饭馆等级, 剩余容量) 人，其中30%向下取整保底当前可服务最高品级客人；冷却20秒。 |

## 时间、状态与保存

- 引擎每 Tick 推进1模拟秒；1×、2×、5×只改变推进速度，不改变规则。
- 满灶订单先进先出；成品不再占用灶眼。手动出餐优先完成最早的成品。
- 现金按分计算；结账、材料和铭牌掉落只发生一次。掉落颜色按客人品级对应红/绿/蓝，食材和铭牌独立判定。
- 初始资源为0、用餐固定5秒；“优先”高级菜缺货时，在该顾客接受范围中回退。已点单菜品下架后仍完成原订单。
- 厨师升级按速度比例调整在制订单；只消除整数边界的浮点噪声，保留真实小数时长。
- 暂停、切后台、打开帮助/设置弹窗时停止计时。暂停时可操作礼物，独立实验还可逐秒推进。
- 自动保存现金、食材、铭牌、等级、已激活菜、上架菜单、抽奖保底和随机状态。刷新会重建客人与营业日统计、清空临时效果，不计算离线收益。
- 损坏或不兼容的存档保留原始内容并停止覆盖；设置中可导出备份或导入有效存档。实验状态不会写入正式存档。

## 测试和验收

`npm test` 使用 Node 内置 node:test，当前64项测试，覆盖 T01–T14、配置数值、概率区间、超时、容量、升级、礼物上限、多灶仙女棒、浮点计时、存档、声音、布局和重复启动。长时间测试使用多个固定种子模拟经营，检查资源、桌位、灶眼与队列不变量。

`npm run build` 生成静态构建；`npm run verify` 检查页面/CSS资源、脚本语法和构建后经营闭环。

手工验收步骤见 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。游戏右上角设置 → 验收与规则，可选择排队、成品超时、研发成长、厨师锁、保底抽奖、礼物上限、多灶仙女棒等独立场景。实验暂停后点击“推进1秒”可精确验证时间边界；刷新或“回到我的饭馆”恢复正式进度。

自动测试不代表所有浏览器兼容性、声音听感和真人试玩均已验证。

## 工程目录

```text
index.html / styles.css  页面与固定9:16布局
start.bat                Windows启动入口
package.json             命令与Node版本
src/config.js            数值配置
src/engine.js            纯经营引擎、状态与存档序列化
src/app.js               交互、渲染、统一时钟
src/storage.js           异常存档保护
src/scene-layout.js      桌位、座位、脚点与移动路径
src/presentation.js      DOM更新与视觉反馈
src/audio.js             声音控制与设置
assets/                  本地图片和音频
scripts/                 启动、构建、验证、打包、音效合成
tests/                   自动化测试
docs/                    架构、验收、美术与音频说明
dist/                    构建后生成；项目ZIP内附带
```

架构与状态机见 [docs/DESIGN.md](docs/DESIGN.md)。图片使用AI生成并随项目保存，界面与布局由代码实现；声音为程序合成，详见 [docs/ART.md](docs/ART.md) 和 [docs/AUDIO.md](docs/AUDIO.md)。不需要运行时生图或联网请求。

`npm run audio:build` 可离线重新合成音频。`npm run package` 会先构建、测试和验证，再在 delivery/ 生成“百味饭馆.zip”；外层只含“项目.zip”和本 README，项目包排除 Target、过程截图、旧交付文件、Git历史与缓存。演示视频单独录制和提供。
